### Операционни капани (наследени, потвърдени)

- **Не пускай `npm run build` докато `next dev` работи.** Споделената `.next`
  папка се чупи → `ChunkLoadError` / страница без CSS / `MODULE_NOT_FOUND` за
  `vendor-chunks`. Лек: спри dev процеса, `Remove-Item -Recurse -Force .next`,
  `npm run dev`. Не е симптом за проблем в кода.
- **`next dev` оставя осиротяло дете, което държи порт 3010.** `Stop-Process`
  на родителя не го убива. Симптом: `EADDRINUSE: address already in use :::3010`
  при рестарт, или — по-подло — localhost сервира **стара версия от друг клон**
  и изглежда „счупен“. Коварното е, че
  `Get-NetTCPConnection -State Listen -LocalPort 3010` може да върне празно,
  защото сокетът е на IPv6. Диагностика и лек:
  ```
  Get-NetTCPConnection -LocalPort 3010 | Select-Object State, OwningProcess
  Stop-Process -Id <PID> -Force
  Remove-Item -Recurse -Force .next
  npm run dev
  ```
  **Винаги проверявай `git branch --show-current` преди да гледаш localhost** —
  dev сървърът не знае, че си сменил клона.
- **`npm run build` НЕ прави type-check** — `next.config.ts` има
  `typescript.ignoreBuildErrors: true` + `eslint.ignoreDuringBuilds: true`.
  За типова проверка: `npx tsc --noEmit`, но там има **заварени** грешки в
  `a2/types.ts`, `b1/types.ts` и някои уроци — не са регресия, извън обхвата.

- **Непрефиксиран ключ в `<level>/exercise-components.ts` е тих leak към A1.**
  Не добавяй такива.
- `rg` не е в PATH на тази машина — ползвай Grep tool-а, не `rg` в терминала.
  `| cat` в PowerShell гърми — не го ползвай в git команди.

### Механизъм А — `instructionKey` (за инструкции и самостоятелни UI фрази)

Инструкцията в content файла се заменя с ключ, а преводите живеят в

```ts

```

```ts
// в src/i18n/a2.ts — 7 езика, ВИНАГИ в този ред
export const A2_TRANSLATIONS = {
  'a2.instr.selectCorrectForm': {
    bg: 'Изберете правилната форма.',
    ar: 'اختر الصيغة الصحيحة.',
    fr: 'Choisissez la forme correcte.',
    en: 'Choose the correct form.',
    fa: 'شکل درست را انتخاب کنید.',
    uk: 'Виберіть правильну форму.',
    ru: 'Выберите правильную форму.',

```

**A2 вече има 60 такива ключа и 75 употреби — тази работа е СВЪРШЕНА.**

### Механизъм Б — inline `Record<lang>` слот (за заглавия и вградено съдържание)

Преводите стоят до българското в самия content файл. Тук **`bg` НЕ се пише** —
българското е в основното поле:

```ts
title: 'Адрес и диалози',              // българското
titleI18n: {                            // 6 езика, БЕЗ bg
  en: 'Address and dialogues',
  fr: 'Adresse et dialogues',
  ar: 'العنوان والحوارات',
  fa: 'نشانی و گفتگوها',
  uk: 'Адреса та діалоги',
  ru: 'Адрес и диалоги',
},
```

**Това е механизмът за разделите (Фази 3–4).**

### Механизъм В — pretranslate кешът (за всичко останало)

Всичко, което няма слот — заглавия на упражнения, описания на уроци, речникови
глоси, имена на секции в тестове — минава през скрипта. Не се пише на ръка:

```
npm run pretranslate -- --level a2 --all
```

Скриптът обхожда съдържанието, вади българските стрингове, пуска ги на GPT-5.5
на батчове с контекст за урока, и пише резултата в
`src/i18n/generated/translations.json`. Ключът е **суровият български текст**,
не хеш. По време на работа `useTranslate()` търси в този ред:
`translationOverrides.ts` → `generated/translations.json` → `localStorage` кеш →
жив Google Translate. Затова празен слот **никога не чупи UI** — просто пада на
по-лошо качество.

### Кое НИКОГА не се превежда

Самото учебно съдържание — българските думи, изречения и **верни отговори**,
които ученикът упражнява. Речниковият гло̀с (значението) се превежда;
българската заглавна дума остава българска.

## 2. Как се правят разделите (`sectionStart`)

### Какво прави разделът визуално

`src/components/LessonParts.tsx` групира упражненията: **всяко упражнение с
`sectionStart` открива нова сгъваема част.** Упражненията между два
`sectionStart` попадат в първата от тях. Без нито един `sectionStart` урокът се
рендерира като плосък списък — това е състоянието на A2 днес.

Всяка част получава номер („Част 1“), икона според `theme`, българско заглавие
като основен ред и преведено заглавие като втори ред за неб­ългарски езици.

### Стъпките, в ред

**Стъпка 1 — прочети структурата икономично.** Файловете са 660–1824 реда.
**Не** ги чети целите. Извади само скелета през Grep:

```
pattern: ^\s+(id|type|title|order):
path: src/content/a2/lessons/a2-lesson-NN/exercises.ts
```

Това дава списък от упражнения с типовете им — достатъчно, за да се видят
границите.

**Стъпка 2 — намери границите.** Естествените граници в тези уроци са там,
където започва нов тематичен блок. Разпознават се по `title` и по `type`:

| Сигнал за нова част | Пример |
|---|---|
| `title: 'НОВИ ДУМИ N'` или `type: 'illustrated_cards'` след упражнения | нов речников блок |
| `title: 'ГРАМАТИКА N'` или `type: 'grammar_table'` / `grammar_examples` | нов граматичен блок |
| `title: 'ДИАЛОЗИ N'` или `type: 'dialogues'` | нов диалогов блок |
| `type: 'reading_text'` с ново заглавие | нов текст за четене |

Цели **4–6 части на урок** (A1 има 4–7). Твърде много части правят урока
накъсан; твърде малко не помагат.

**Стъпка 3 — измисли българското заглавие.** Заглавието описва **темата** на
частта, не типа упражнение:

- ✅ „Адрес и диалози“, „Предлози, посоки и числа“, „Текстове за градове и села“
- ❌ „НОВИ ДУМИ“, „ГРАМАТИКА 1“, „Част 2“, „Упражнения“

`subtitle` е по избор — слагай го само когато добавя стойност (виж §C1 в
[content-quality-checklist](../.cursor/rules/content-quality-checklist.mdc)).
Ако повтаря заглавието, махни го.

**Стъпка 4 — избери `theme`.** Само пет стойности са валидни; те определят
иконата:

| `theme` | За какво |
|---|---|
| `'vocabulary'` | речников блок, НОВИ ДУМИ, карти с думи |
| `'grammar'` | граматични таблици, примери, правила |
| `'dialogue'` | диалози, изграждане на диалог |
| `'reading'` | текстове за четене, четива |
| `'review'` | преговорни / допълнителни упражнения |

**Стъпка 5 — преведи на 6 езика** по Механизъм Б по-горе. Български термин в
превода се оставя в кавички + гло̀са в скоби: `„живея" (to live)`,
`«улица» (شارع)`.

**Стъпка 6 — вмъкни.** Точката за вмъкване е **веднага след `order: N,`** на
първото упражнение на частта. Ползвай прицелен StrReplace с достатъчно контекст
(id-то на упражнението отгоре), за да е уникален:

```ts
    id: 'a2-l01-dialozi-01',
    type: 'dialogues',
    title: 'ДИАЛОЗИ 1',
    order: 2,
    sectionStart: {          // ← вмъкнатото започва тук
      title: '…',
      subtitle: '…',
      titleI18n: { … },
      subtitleI18n: { … },
      theme: 'dialogue',
    },                       // ← и свършва тук
    sections: [              // ← съществуващото продължава непокътнато
```

**Стъпка 7 — докажи, че не си пипнал съдържание:**

```
git diff --numstat HEAD -- src/content/a2/lessons/a2-lesson-NN/exercises.ts
```

Изходът е `<добавени> <изтрити> <файл>`. **Изтритите ТРЯБВА да са 0.** Ако не
са — нещо е пренаписано и промяната се отхвърля.

**Стъпка 8 — линт:**

## 3. Как работят празненствата

Логиката е в `src/lib/celebration.ts` и е **изцяло data-driven** — няма нищо за
писане в съдържанието. Гейтът е един Set:

```ts
export const CELEBRATION_ENABLED_LESSONS = new Set<string>([
  'lesson-01', 'lesson-02', /* … A1 … */ 'lesson-11',
  // тук се добавят A2 id-тата
]);
```

`buildCelebrationPlan()` взима урока и:
1. Групира упражненията по `sectionStart` — **същото групиране като страницата**.
2. За всяка част намира **последното проверимо** упражнение (типовете без
   „Провери“ бутон са в `NON_CHECKABLE_TYPES` — таблици, диалози, карти, текстове).
3. Това упражнение става спусък: щом ученикът го завърши, излиза малък toast
   „следва: <име на следващата част>“.
4. Workbook масивът („Преговор“) е автоматично финалната част — там излиза голям
   модал с бутон „Напред“ към следващия урок или тест.

Следствия, които трябва да знаеш:
- **Без `sectionStart` планът е празен.** Затова празненствата идват СЛЕД
  разделите, не преди.
- Ако урок няма workbook, **последната част става финалът** — коректно
  поведение (`celebration.ts:196-206`), не бъг.
- Ако част се състои само от непроверими упражнения (само таблици например), тя
  не получава спусък и се прескача. Това е нормално.

Затова Фаза 5 е буквално добавяне на 11 реда в един Set — цялата останала логика
вече работи.
